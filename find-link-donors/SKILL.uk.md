# find-link-donors (UA)

Самостійний скіл: витягнути список кандидатів-донорів для лінкбілдингу з **Collaborator.pro Public API** на базі критеріїв користувача, показати їх посторінково як Markdown-таблиці зі статистикою і згенерувати фінальний CSV.

Цей скіл **не залежить** від жодного іншого інструмента, CLI чи джерела даних. Тільки Collaborator.pro Public API + локальний `.env` з ключем.

---

## ЗАВДАННЯ

Знайти донорів для лінкбілдингу через Collaborator.pro Public API.

## API

- **Base URL:** `https://collaborator.pro`
- **Endpoint:** `GET /api/public/creator/list`
- **Auth:** header `X-Api-Key: $COLLABORATOR_API`
- **Spec:** `https://collaborator.pro/es/api/public/default/schema` (OpenAPI 3.0)
- **Docs UI:** `https://collaborator.pro/api/public/default/docs`

## КЛЮЧ

Зчитай ключ `COLLABORATOR_API` з `/Users/andrei/PY/.env`.
Якщо файла нема або змінної в ньому нема — **спитай користувача**, не вгадуй назву файла.

## ВАЖЛИВЕ ОБМЕЖЕННЯ ДОСТУПУ

Endpoint `/creator/list` позначений у spec як **"available upon request from support"**.
Якщо отримаєш `401`/`403` — **не зациклюйся**: зупинись і повідом користувача, що треба запросити в Collaborator активацію Creator API для акаунта.

---

## ВВІД ВІД КОРИСТУВАЧА

Користувач формулює критерії довільно. Типовий набір:

- мінімальний DR (Ahrefs)
- динаміка трафіку (зростає / стабільний / будь-який)
- мінімальний органічний трафік
- мова сайту
- країна сайту
- тип лінка (dofollow / nofollow)
- мінімальний вік домену
- максимальна ціна публікації
- тип сайтів (personal blog / corporate blog / mass media / online store / information site / portal / publisher)
- формат розміщення (стаття, лінк-вставка тощо)

Якщо якогось критерію немає — **не вигадуй**, не додавай. Питай, якщо треба.

## КРОК 1 — РЕЗОЛВ СЛОВНИКІВ (один раз перед основним запитом)

1. `GET /api/public/dictionary/languages` → знайди ID мови, що відповідає вводу користувача (наприклад "Ukrainian" / code `ua`).
2. `GET /api/public/dictionary/countries` → знайди ID країни.

**Виведи обидва ID користувачу** перед запуском основного запиту.

---

## КРОК 2 — МАПІНГ КРИТЕРІЇВ → ПАРАМЕТРИ API

| Критерій користувача | Параметр API |
|---|---|
| DR ≥ N | `ahrefs_dr_min=N` |
| Трафік зростає | `is_traffic_grown=true` |
| Трафік ≥ N / міс | `ahrefs_traffic_min=N` (абсолютні значення Ahrefs organic; параметр `_traffic` — у тисячах, менш надійний) |
| Мова | `_language=<LANG_ID>` (з кроку 1) |
| Країна | `countries=<COUNTRY_ID>` (з кроку 1) |
| Dofollow | `nofollow=0` (⚠️ `0 = Dofollow`) |
| Вік ≥ N років | `_domain_age=N` |
| Ціна ≤ N USD | `_price_max=N` (+ перевір валюту у відповіді: `prices[].pricePublication` містить суфікс валюти; якщо не USD — фільтруй клієнтсько) |
| Тип сайтів | `_cre_type_id[]=<ID>` (повторюється) |
| Формат — стаття | `format_id=1` |

**Довідник типів сайтів (`_cre_type_id`):**
- `1` = Personal blog
- `2` = Corporate blog
- `3` = Mass media
- `4` = Online store
- `5` = Information site
- `6` = Portal
- `7` = Publisher

---

## КРОК 3 — СОРТУВАННЯ

Параметр `sort` є, але значення в spec **не задокументовані**.
Спробуй у такій послідовності, поки запит не поверне коректно відсортовану вибірку:

1. `sort=-ahrefs_dr`
2. `sort=ahrefs_dr_desc`
3. `sort=-dr`

Якщо жоден варіант не працює — сортуй **клієнтсько за DR (DESC)** після вивантаження сторінок.

---

## КРОК 4 — ПАГІНАЦІЯ

API обмежує `per-page` значеннями **[20, 40, 60, 100]** — `10` не підтримується.

- Використовуй `per-page=20`.
- **Виводь** результати шматками по **10 рядків** у таблиці.
- Після кожних 10 — **пауза + питання** «продовжити?».
- Використовуй `pagination.totalCount` з відповіді, щоб показувати прогрес:
  > «сторінка X з Y, всього кандидатів N, після клієнтських фільтрів залишилось M».

---

## КРОК 5 — ПЛАН ЗАПИТУ (ПОКАЖИ ПЕРЕД ВИКОНАННЯМ)

Перед першим викликом `/creator/list` — виведи користувачу:

- повний URL з усіма query-параметрами (ключ **маскуй як `***`**);
- які фільтри застосовані сервером, а які — клієнтсько;
- очікувану валюту цін.

**Дочекайся явного `go`** від користувача перед першим запитом.

---

## КРОК 6 — ФОРМАТ ВИВОДУ

Для кожних 10 валідних донорів — таблиця Markdown:

| # | Domain | Site Type | Country | Traffic | Site Age | Categories | Price | Link | Collaborator URL |
|---|--------|-----------|---------|---------|----------|------------|-------|------|------------------|

Поля з відповіді API:

- **Domain** → `name`
- **Site Type** → `siteType`
- **Country** → `country`
- **Traffic** → `traffic` (рядок типу `"353.1 k"`)
- **Site Age** → `siteAge`
- **Categories** → `categories` (скоротити до перших 3)
- **Price** → `prices[0].pricePublication`
- **Link** → `prices[0].linkType` (підсвітити, якщо ≠ `dofollow`)
- **Collaborator URL** → `url`

DR окремою колонкою **не виводь** — у `CreatorFull` його нема як поля, лише як фільтр. Якщо треба показати — зазнач у заголовку: «DR ≥ N (за фільтром)».

**Під кожною таблицею:**
- скільки відкинуто клієнтськими фільтрами і чому (тематика / валюта / dofollow / інше);
- середня ціна, медіана трафіку;
- скільки залишилось у пулі (з `pagination.totalCount`).

## ОБМЕЖЕННЯ Й ОБЕРЕЖНІСТЬ

- **Rate limit:** пауза `0.5–1` сек між сторінками.
- **5xx відповіді:** 2 ретраї з експоненційним бекофом, далі зупинись і повідом.
- **Ключ:** не друкуй у логах і в плані запиту — маскуй як `***`.
- **Сирий JSON кожної сторінки** збережи в:
  `/Users/andrei/PY/collaborator-pro-skills/find-link-donors/output/donors_<YYYY-MM-DD>_p<N>.json`
  для подальшого аналізу.
